# Brako Vault — セキュリティと透明性

[English](../SECURITY.md) | [Español](SECURITY.es.md) | [Português](SECURITY.pt.md) | [Français](SECURITY.fr.md) | [Deutsch](SECURITY.de.md) | [Italiano](SECURITY.it.md) | **[日本語](SECURITY.ja.md)** | [简体中文](SECURITY.zh-CN.md)**

最終更新: 2026-09-05

このドキュメントは、Brako Vault がデバイス上のデータをどのように
保護するかを説明します。ここにある事実上の記述は、すべて公開されて
いる[暗号パラメータの正本ファイル](https://github.com/waar19/brako-vault/blob/main/docs/canonical-crypto.md)
(ソースリポジトリ内)から導かれるか、公開されている APK とアプリの
マニフェストから直接検証できます。「設計されている」が「監査済み
ではない」記述については、その旨を本文に明記しています。

> **ソースコードは非公開です。** アプリのソースコードは本リポジトリ
> には含まれていません。以下の数値・サイズ・プロトコルは、アプリが
> 実際に行う処理の、公的な権威ある宣言です。リリース APK は、非公開
> リポジトリの `Argon2Spec` と `BvdaConstants` に定義された定数を
> 持つ同じコードからビルドされています。

## 1. 暗号化

| 項目 | 方式 | パラメータ |
|------|------|------------|
| 共通鍵暗号 | AES-256-GCM (NIST SP 800-38D) | 256 ビット鍵、128 ビット認証タグ、書き込みごとに 96 ビット (12 バイト) の nonce |
| 鍵導出 | Argon2id (RFC 9106) | 64 MiB (65 536 KiB)、3 反復、4 lanes、16 バイト salt、32 バイト派生鍵 |
| 保管庫ごとの salt | ランダム 16 バイト | 作成時に暗号学的に安全な乱数源で生成 |
| 書き込みごとの nonce | ランダム 12 バイト | 書き込みごとに一意。同じ鍵で再利用しない |
| ヘッダの完全性 | 暗号文に紐付け | ヘッダの先頭 46 バイトを Additional Authenticated Data (AAD) として認証 |

**「タグ」とは何か。** AES-GCM は 128 ビットの認証タグを生成し、
暗号文に付加します。ファイル (magic、KDF パラメータ、salt、nonce、
暗号文のいずれか) に 1 ビットでも改変があればタグ検証が失敗し、
保管庫は開かず拒否します。

**「nonce」とは何か。** 12 バイトの nonce は、同じ鍵の元で決して
繰り返してはならない値です。アプリは保存のたびに新しいランダム
nonce を生成します。nonce の再利用は壊滅的な結果をもたらすため、
乱数源が壊れた場合は実装が明示的に安全側に失敗します。

## 2. ファイル形式

保管庫のデータはすべて単一ファイル `vault.bvda` に格納されます。

レイアウト (マルチバイトフィールドはビッグエンディアン。`saltLen` と
`nonceLen` は 1 バイト):

```
 オフセット  サイズ  フィールド
 --------  ------  --------
   0          4    magic            = "BVDA" (ASCII)
   4          1    formatVersion    = 0x01
   5          1    kdfId            = 0x01 (Argon2id)
   6          1    aeadId           = 0x01 (AES-256-GCM)
   7          1    kdfParallelism   = 0x04
   8          4    kdfMemoryKiB     BE = 65 536
  12          4    kdfIterations    BE = 3
  16          1    saltLen          = 0x10 (16)
  17         16    kdfSalt
  33          1    nonceLen         = 0x0C (12)
  34         12    aeadNonce
  46          4    ciphertextLen    BE  <- AAD には含まない
  50          N    ciphertext (N = ciphertextLen、末尾に 16 B タグ)
```

ヘッダの先頭 46 バイトが AAD です。タグは暗号文の一部なので、
ファイルの認証対象範囲は暗号文長 4 バイトを除く全領域をカバー
します。

## 3. アトミック書き込み

すべての保存は「書いてから名前変更」のパターンに従います。アプリは:

1. 新しい保管庫を `vault.bvda.tmp` に書き出す。
2. 一時ファイルに対して `fsync` を呼ぶ。
3. ディレクトリに対して `fsync` を呼ぶ。
4. `vault.bvda.tmp` を `vault.bvda` にアトミックにリネームする。

途中で電源が落ちたりアプリが殺されたりしても、既存の
`vault.bvda` はそのまま残り、一時ファイルは次回保存成功時に
掃除されます。

## 4. 生体認証による鍵保護

生体認証ロックを有効にしている場合、派生鍵は Android Keystore に
保管された鍵でラップされます。Keystore に守られた鍵は:

- 端末が Trusted Execution Environment (TEE) または StrongBox
  Keymaster を持つ場合、安全なハードウェアから決して出ない。
- ユーザーモードのプロセスからは抽出できない。
- ユーザが端末の生体情報をすべて削除した、ロック画面を変更した、
  または工場出荷時リセットを行った時点で無効化される。

生体認証のプロンプトは OS が強制するもので、アプリはこれを
バイパスできません。

## 5. パスワード復元なし

復元手段も、メールアドレスによるリセットも、復元鍵も、保管庫を
開けられるカスタマーサポートも存在しません。マスター
パスワードが唯一の鍵であり、保存されることはなく、送信される
ことはなく、ログに記録されることもありません。マスター
パスワードを紛失すると、保管庫も失われます。

本プロジェクトの作者であっても、あなたの保管庫を開くことは
できません。

## 6. 脅威モデル — Brako Vault が守るもの

このアプリは以下に対する保護を意図しています:

- 電源オフ状態の端末の盗難: マスター
  パスワードを持たず、Android のディスク暗号化を迂回する手段も
  持たない攻撃者からの保護。
- ネットワーク経由の攻撃: アプリには `INTERNET` 権限がないため、
  ネットワークが侵害されても保管庫を外部に持ち出すことは
  できない。
- 保管庫ファイルのリプレイや改竄: 1 ビットでも変更があれば
  AES-GCM のタグ検証で検出される。
- マスターパスワードへの総当たり: 64 MiB・3 反復の Argon2id が
  1 回ごとの推測を高コストにする。オフラインの攻撃者でも最終的に
  パスワードを推測する必要がある。

以下のことは **対象としていません**:

- 保管庫が開いている間に動作している、侵害済みまたは root 化された
  端末。マスターパスワードが認証された時点で鍵はメモリ上にある
  ため、プロセスは平文にアクセスできる。
- ショルダーハッキング、キーロガー、アプリと同じ UID で動作する
  マルウェア。
- 強要: アンロック済み端末への物理アクセスを持つ決意した攻撃者
  は保管庫を読める。
- 弱く再利用されているマスターパスワード。Argon2id は推測を遅く
  するが「123456」を安全にはしない。
- ユーザ自らの意思による、暗号化されていない保管庫の第三者への
  エクスポート。

## 7. バックアップ

アプリは `.bvda` ファイル(ディスク上の保管庫と同じ暗号化形式)を
エクスポートします。エクスポートしたファイルは、ユーザが明示的に
「パスワードなしでエクスポート」を選択しない限り、マスター
パスワードから派生した同じ鍵で暗号化されます。後者を選んだ場合、
アプリはそのファイルが保護されないことを大音量で警告します。
端末のバックアップ機構は既定で無効化されており、`adb backup`
やクラウドバックアップに保管庫が含まれないようにしてあります。

## 8. オフライン同期

Brako Vault にはサーバーがありません。端末間の同期は、ユーザが
選んだチャネル(USB、メール、クラウドストレージ、AirDrop 風
共有)を通じて `.bvda` ファイルを交換する形で行われます。アプリは
ネットワークソケットを開かないため、チャネル自体をアプリが
観察することはできません。ファイルは AES-GCM のタグ検証により
エンドツーエンドで認証されるため、改竄されたコピーを仲介する
第三者はインポート時に検出されます。

## 9. 宣言された権限

APK は正確に 3 つの権限だけを宣言します:

| 権限 | 理由 |
|------|------|
| `android.permission.CAMERA` | 2FA トークンを含む QR コードをスキャンするため。カメラはユーザが QR スキャナを開いたときだけ使用され、フレームは端末上で処理され、保存されることはない。 |
| `android.permission.VIBRATE` | ロック解除成功やクリップボードへのコピーといったアクションの触覚フィードバックのため。 |
| `android.permission.USE_BIOMETRIC` | 任意の生体認証ロックを、Android Keystore を介して可能にするため。アプリは生体データに直接アクセスしない。 |

APK は `android.permission.INTERNET` を **宣言しません**。
フォールバックも、「デバッグビルドのみ」の例外も、それを要求する
第三者 SDK もありません。将来追加する機能でネットワーク
アクセスが必要になった場合は、その機能自体を見直し、権限は
追加しません。

## 10. APK に INTERNET 権限がないことを確認する方法

このドキュメントを信用しなくても構いません。任意の端末または
ワークステーションで以下を実行して検証できます:

```shell
# Android SDK build-tools から:
aapt2 dump permissions brako-vault-vX.Y.Z.apk
# または
aapt dump permissions brako-vault-vX.Y.Z.apk
```

出力には §9 の 3 つの権限だけが並んでいなければなりません。
`android.permission.INTERNET` が現れたら、そのファイルは公式
APK ではないため、インストールしないでください。

## 11. バイナリの来歴と署名

各リリースはメンテナのリリース鍵で署名されています。指紋は
リリースノートで公開されています。ローカルでの検証は:

```shell
apksigner verify --verbose --print-certs brako-vault-vX.Y.Z.apk
```

署名証明書の SHA-256 指紋が、リリースノート記載のものと一致する
必要があります。各成果物のチェックサムは、同じリリースのバイナリ
と同じ場所にある `SHA256SUMS.txt` に掲載されています。

## 12. 保証レベル

Brako Vault は明示的に 3 つの保証レベルを提示します。これらは
同じものではありません:

- **設計済み (Designed)。** 本ドキュメントのアーキテクチャと
  パラメータ選定は、作者が実装すると約束した内容です。最も弱い
  主張です。
- **自動テスト済み (Automatically tested)。** 非公開のソース
  リポジトリにあるテストスイート — `CryptoSpecDocTest`、
  `jvmTest`、`androidApp:testDebugUnitTest` — がプッシュごとに
  実行され、暗号パラメータおよびマニフェストに `INTERNET` が
  ないことを含め、本ドキュメントの記述と実装が一致することを
  検証します。
- **外部監査済み (Externally audited)。** Brako Vault は外部
  監査を **受けていません**。作者は外部認証、Common Criteria
  評価、第三者ペネトレーションテストを主張しません。将来的に
  監査が実施された場合、その所見は日付・範囲・完全報告書とともに
  ここに公開されます。

## 13. 脆弱性の報告

脆弱性を発見した場合は、`security@brakovault.example` まで
メールしてください(プロジェクトが実アドレスを公開したら差し替えて
ください)。セキュリティ上機微な報告について、公開 GitHub Issue
を提出しないでください。著者は 72 時間以内に受領確認を、確認済み
の問題については 30 日以内に修正または文書化されたリスク受容を
提供することを約束します。
